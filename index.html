Duas portas, dois públicos

A agenda de uma barbearia não é uma agenda só: é a de cada barbeiro, com o serviço que cada um faz, no tempo que cada um leva. Quem marca está na rua, com pressa; quem atende está com a máquina na mão.

A vitrine

no celular do cliente

Cada barbearia tem o próprio endereço. O cliente vê a equipe e os preços, escolhe e confirma com nome e WhatsApp — sem criar conta, sem instalar nada.

  • Serviço, barbeiro e horário, nessa ordem
  • Só aparecem horários que cabem de verdade
  • Confirmação e cancelamento no WhatsApp
  • Lembrete uma hora antes, uma vez só

O painel

com login, para quem trabalha

Onde o dia vira fila: quem vem agora, quem vem depois e qual é o próximo horário livre de cada um — para o cliente parado no balcão.

  • Expediente, folga e pausa por barbeiro
  • Cada barbeiro com a própria duração para cada serviço
  • Encaixe do balcão direto na agenda
  • Barbeiro entra por convite, que chega pelo WhatsApp
  • O WhatsApp da própria barbearia, conectado por QR

Quem enxerga o quê

Três alcances, e a fronteira é aplicada na API — não só escondida na tela.

Plataforma

Em admin., fora de qualquer barbearia: cria casas com o primeiro dono, liga, desliga e reemite o convite.

Dono

A própria barbearia inteira: agenda de todos, equipe, catálogo e horários de cada um.

Barbeiro

A própria agenda, os próprios horários e o tempo que ele leva em cada serviço.

Quatro decisões que explicam o resto

O isolamento mora no banco

O Postgres tem Row Level Security nas tabelas de cada barbearia, e a aplicação roda num papel sem DDL. Um SELECT esquecido não vaza a agenda do vizinho — ele volta vazio.

A duração é do barbeiro, não do serviço

O motor de horários cruza expediente, bloqueios, o que já foi vendido e o tempo que aquele barbeiro leva. Barbeiro rápido cabe mais gente no dia, e a agenda reflete isso sozinha.

404, nunca 403

Ação sobre registro de outro barbeiro responde que não existe. 403 confirmaria que existe. Pelo mesmo motivo, /admin dá 404 em qualquer subdomínio de barbearia.

WhatsApp fora do ar não desfaz nada

O envio é fire-and-forget e sai do Django, nunca do navegador. Se o zap cair, o horário continua marcado e o convite continua valendo.

Como é feito

Dois repositórios independentes, cada um com o seu Docker Compose, ligados como submódulos no repositório guarda-chuva. Deploy em Coolify.

Backend

Marcai-back

  • Python · Django base e API
  • Postgres Row Level Security por barbearia
  • Celery + Redis lembretes e envios
  • Evolution API WhatsApp auto-hospedado
  • argon2 senhas
  • pytest testes contra banco real

Frontend

Marcai-front

  • Next.js 16 App Router
  • React 19 · TypeScript componentes e tipos
  • Tailwind CSS estilo
  • jose sessão em cookie HTTP-only
  • zod · date-fns validação e datas
  • Vitest testes
